ZAHRAH LUXURY BOUTIQUE - ARCHITECTURE & COMPONENTS DOCUMENTATION
===================================================================

This document provides a comprehensive overview of the components, pages, and services built for the Zahrah Luxury Boutique web application. It is structured to help any AI assistant or developer understand the system's architecture and codebase.

---

1. PAGES (/pages)
The application uses React Router to navigate between these top-level pages.

* Home.tsx: The main storefront landing page. It orchestrates various dynamically configurable sections (like banners, new arrivals, collections, lookbooks) based on the layout configuration fetched from Firestore.
* ProductDetail.tsx: The individual product page displaying images, details, stock status, variants (size, color), and handles the "Add to Cart" or "Restock Request" actions.
* Checkout.tsx: The secure checkout flow. It validates stock in real-time against Firestore, integrates with Paystack for payments, and handles abandoned checkout drafts if the user closes the payment popup prematurely.
* Lookbook.tsx: A gallery-style page displaying curated outfits/looks, allowing users to purchase items directly from a styled photograph.
* Admin.tsx: The shell for the secure Admin Portal. It verifies user permissions and renders the appropriate dashboard tabs based on the staff member's role (Super Admin, Manager, Support, Viewer).
* Authentication (Login.tsx, Signup.tsx, ForgotPassword.tsx): Handles user authentication via Firebase Auth.
* User Portal (Orders.tsx, Wishlist.tsx): Allows authenticated users to view their past orders, track statuses, and manage saved items.
* CMS Pages (InfoPage.tsx, PrivacyPolicy.tsx, NotFound.tsx): Dynamically rendered informational pages and the 404 fallback page.

---

2. ADMIN DASHBOARD COMPONENTS (/components/Admin)
The admin portal is heavily modularized into specialized tabs to manage every aspect of the boutique.

* DashboardTab.tsx: The main analytics overview showing revenue graphs, recent orders, top products, and conversion metrics.
* ProductsTab.tsx: A full CRUD interface for managing the product catalog, categories, and brands. Includes image uploads to Cloudinary.
* OrdersTab.tsx: Interface for viewing all customer orders, updating fulfillment statuses (Pending, Shipped, Delivered), and viewing payment details.
* CustomersTab.tsx: A CRM view listing all registered users and guests who have made purchases. Admins can view customer lifetime value and manually trigger personalized abandoned cart emails.
* RequestsTab.tsx: Manages out-of-stock "Restock Requests" from users. Admins can bulk-email users when an item comes back in stock using the automated email templates.
* AbandonedTab.tsx: Tracks incomplete checkouts (abandoned carts) to help recover lost sales.
* LayoutTab.tsx: A visual drag-and-drop CMS that allows admins to control the exact layout of the Home page (reordering sections, updating banners, assigning products to specific collections).
* StaffTab.tsx: Role-Based Access Control (RBAC) management. Super Admins can add/remove staff members and assign roles (Manager, Support, Viewer).
* PagesTab.tsx: A simple text/HTML editor to manage dynamic content pages (like About Us, Shipping Policies).
* PricingTab.tsx: A bulk-editor specifically focused on quickly updating product prices.
* ActivityLogTab.tsx: An audit trail that logs every action taken by staff members in the admin panel for security and accountability.
* AdminSidebar.tsx & AdminMobileHeader.tsx: The navigation layout for the admin portal.

---

3. GLOBAL COMPONENTS (/components)
Reusable UI elements shared across the application.

* Navbar.tsx: The primary navigation bar, handling the shopping cart flyout, user account dropdown, and mobile menu.
* ProductCard.tsx: The standard display card for a product, used in grids, carousels, and search results.
* RestockModal.tsx: A popup that allows users to submit their email/WhatsApp when a product is sold out.
* WhatsAppBot.tsx: A floating widget allowing customers to quickly reach out to support via WhatsApp.
* ReceiptTemplate.tsx: The visual layout used to generate downloadable PDF receipts for orders.
* LuxuryLoader.tsx & InfiniteMarquee.tsx: UI embellishments that give the site a premium, high-end feel.
* CookieConsent.tsx & ErrorBoundary.tsx: Standard compliance and stability wrappers.

---

4. BACKEND SERVICES (/services)
The abstraction layer connecting the React frontend to Firebase and other external APIs.

* dbUtils.ts: The core Firestore data layer. Contains functions for saving/fetching orders, updating products, managing user profiles, and handling abandoned checkouts.
* firebaseConfig.ts: Firebase SDK initialization (Auth, Firestore, Storage, Analytics).
* adminPermissions.ts: Logic for resolving a user's role and determining what actions (create, read, update, delete) they are allowed to perform in the Admin panel.
* emailTemplates.ts: Contains the HTML structure for beautiful, luxury-branded transactional emails (Order Confirmation, Restock Alert, Abandoned Cart).
* emailUtils.ts: Triggers the Firebase Cloud Functions to actually send the emails using the templates.
* cloudinary.ts: Handles uploading product and banner images to Cloudinary's CDN.
* analyticsUtils.ts: Aggregates data for the Admin Dashboard (revenue calculations, sales trends, page views).
* exportUtils.ts: Generates CSV spreadsheets and PDF reports for admin data exports (Orders, Customers, Inventory).
* staffService.ts: Dedicated functions for managing the `staff_members` Firestore collection.

---

5. CORE ARCHITECTURE & DATA FLOW
* State Management: The application relies heavily on React hooks (`useState`, `useEffect`, `useCallback`) alongside real-time Firestore listeners (`onSnapshot`) to keep the frontend instantly synced with the database.
* Cart Persistence: The shopping cart is managed via `localStorage` for guests and synced to Firestore for authenticated users, with a merging strategy upon login (`App.tsx`).
* Security: Firestore Security Rules (`firestore.rules`) rigidly enforce the RBAC system, ensuring that only users with the correct custom claims or staff documents can mutate data, while allowing secure checkout validation for public users.
* Deployment: Built with Vite (`npm run build`) and deployed to Firebase Hosting. Server-side logic (like sending emails) runs on Firebase Cloud Functions.
